# Фаза 6. RAG (9 уроков)

**Действующий инженерный контракт фазы:** устанавливаемый пакет живёт в `src/rag_agent/`; editable install — только dev workflow, release проверяется wheel в 7.8a. Внешние документы и metadata валидируются до индексации; ресурсы индекса/клиентов имеют явного владельца. Обязательные тесты offline и без secrets; рабочие данные обезличены. Commit, tag, push и remote не требуются без отдельного разрешения.

Цель фазы: построить RAG — конвейер «поиск по базе знаний → генерация ответа с опорой на найденное» (retrieval-augmented generation) — на собственной базе знаний CRM-маркетинга.
На выходе ученик умеет: собирать и чистить корпус документов, строить векторный индекс (chromadb, локально), подбирать чанкинг экспериментом, комбинировать точный и смысловой поиск, переранжировать результаты, заставлять модель честно цитировать источники и говорить «не нашёл».
Главный артефакт: репозиторий `rag-agent` — база знаний `knowledge_base/` + пакет `src/rag_agent/` + RAG-агент v1.0 с инструментом `lookup_knowledge`, встроенным в помощника CRM-маркетолога (4.9).
Переиспользуется дальше: вопросы и мини-набор для проверки поиска (6.5) войдут в golden set (7.1); тема внедрения инструкций через документы (6.8) углубляется в 7.6; RAG-агент — один из трёх кейсов портфолио (8.1).

## Урок 6.1. Корпус: сбор и очистка базы знаний CRM

## Урок 6.2. Эмбеддинги: интуиция и руками

**Цель:** ученик понимает, что такое векторное представление текста (эмбеддинг), и умеет считать смысловую близость фраз из своего корпуса.
**До урока:** ничего, кроме предыдущего урока.
**Темы:**
- эмбеддинг — вектор чисел, кодирующий смысл текста; близкие смыслы → близкие векторы
- косинусная близость: интуиция «угол между векторами», без вывода формул
- модель эмбеддингов — отдельная от Claude; корпус на русском ⇒ модель должна быть многоязычной (sentence-transformers, например multilingual-e5-small)

**Артефакт:** `src/rag_agent/embed_demo.py` и выбранная модель эмбеддингов — она же используется в индексе 6.3 и далее во всём конвейере.
