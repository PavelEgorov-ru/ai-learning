# Практика: проекты в рабочем воркспейсе (CRM-workspace-new)

Дополнительная практика курса: 12 карточек-проектов, которые улучшают командный воркспейс `Documents\Claude\CRM-workspace-new\` и вложенные в него инструменты. Составлено Клодом и Кодексом 2026-08-16 по итогам осмотра воркспейса.

## Правила практики

1. **По желанию и без сроков.** Карточки не входят в 74 обязательных урока. Брать можно любую, когда пройдена указанная фаза; количество не ограничено — чем больше практики, тем лучше.
2. **Одна карточка = мини-проект.** Обычно 2–4 сессии. Сессия практики проходит по тем же правилам, что урок (код руками, квиз не нужен, запись в journal.md — обязательна: «практика П<N>, что сделано, что осталось»).
3. **Безопасный контур — закон.** Воркспейс командный: им пользуются коллеги. У каждой карточки указан контур (учебная копия / отдельная ветка / read-only / fixtures). Правило по умолчанию: работаем в отдельной ветке или копии, в `main` командного репозитория учебный код не попадает.
4. **Встройка обратно — отдельное решение.** Довёл проект до рабочего состояния → ревью (можно дуэтом Клод+Кодекс) → осознанное решение админа (тебя) о вливании в `main`. Пункт «Что встроить обратно» в карточке — это цель, а не разрешение мержить сразу.
5. **Секреты и прод** — сквозные правила курса действуют здесь без послаблений: ключи из user-env не светить, прод-ClickHouse только чтение, PII в контекст LLM не попадает.
6. Среда воркспейса — Windows + uv (запин Python 3.13, запуск только `uv run`); это отличие от курсовых проектов в WSL. Практика идёт там, где живёт инструмент.

Порядок: (1) поднять свой сервер параллельно под именем `clickhouse_safe` только у себя; (2) 2–3 недели реальной работы — сравнение логов и удобства с текущим сервером; (3) миграционный план (что сломается у коллег, как откатиться); (4) решение о переключении командного .mcp.json — отдельное, админское. Прод — только чтение, как всегда.
- **Задание:** адаптировать ch-mcp к командному складу (базы mindbox.*, operations.*, ecommerce.*; шаблоны под реальные вопросы коллег); вести журнал сравнения; написать миграционный план и runbook оператора.

- **Критерий готовности:** 2 недели твоей реальной работы через clickhouse_safe без возврата к старому серверу; в audit.jsonl — каждый SQL; миграционный план прошёл ревью (дуэт).
- **Что встроить обратно:** это главная встройка курса в команду — свой безопасный сервер вместо стороннего. Только по итогам периода сравнения.
