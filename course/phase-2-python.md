## Урок 2.0b. Значения, имена, числа и строки

**Цель:** ученик различает значение, его тип и имя; понимает порядок вычисления выражения и осознанно преобразует строку в число.
**До урока:** 2.0a: собственный файл запускается, присваивание и `print` знакомы.

**Вводная:** число из выгрузки и число в расчёте могут выглядеть одинаково, но строка `"12"` и целое число `12` допускают разные операции. Python выбирает поведение по типу объекта. Разберём, какое значение создаёт выражение, к чему после присваивания относится имя и где нужно преобразование, чтобы текст не попал в арифметику.

**Темы:**
- `int`, `float`, `str`; литералы, кавычки и имя без кавычек;
- вызовы `type`, `int`, `float`, `str`, `len`, `round`: назначение, аргумент и результат каждого вводятся до использования;
- `+`, `-`, `*`, `/`, `//`, `%`, `**`, скобки и порядок действий; `/` и округление результата;
- присваивание связывает имя с результатом правой части; повторное присваивание не меняет ранее вычисленные значения других имён;
- строки: соединение, длина, индекс с нуля, срез, `\n`; строку нельзя изменить по индексу;
- простая f-строка для подписи результата; точный формат процентов — позже, в 2.5;
- ошибка преобразования неподходящей строки: прочитать причину, не писать `try/except` заранее.

**Материалы:** Python Tutorial, [Numbers](https://docs.python.org/3.14/tutorial/introduction.html#numbers) и [Text](https://docs.python.org/3.14/tutorial/introduction.html#text), только перечисленные операции.
**Ход сессии:**

В этом уроке знаменатель заведомо положительный; ноль разберём в 2.0c. Проверить смену счётчиков и отдельно объяснить ошибку преобразования текста, который не обозначает число.

## Урок 2.0c. Условия и выбор действия

**Цель:** ученик строит ветвление по данным, различает нулевое значение и отсутствие значения, проверяет границы условия.
**До урока:** 2.0b: числа, строки, присваивание, преобразование, вывод.

## Урок 2.10. Надёжный HTTP: transport, таймауты и retry policy

**Цель:** ученик проектирует HTTP-transport с раздельными connect/read timeout и ограниченной retry policy, которая учитывает метод, идемпотентность, статус, `Retry-After` и общий бюджет попыток.
**До урока:** 2.9: requests, HTTP/JSON и исключения; `crm-tools` уже устанавливаемый пакет `src/crm_tools`.
**Объём:** до трёх сессий. Публичный httpbin допустим только как необязательный smoke; критерии доказываются fake transport или локальным детерминированным сервером.
**Вводная:** connect timeout ограничивает ожидание соединения, read timeout — паузу без байтов при чтении. В Requests это не общий deadline операции. Повторы добавляют время и после read timeout могут повторить уже выполненную сервером операцию. Поэтому политика задаёт, что и сколько раз разрешено повторять. Жёсткая отмена по общему wall-clock deadline появится в async-уроках 7.4a; здесь total retry budget ограничивает запуск новых попыток, но не обещает прервать зависший системный вызов ровно в заданную секунду.
**Темы:**
- `requests.Session` и transport без печати; JSON codec отделён от транспорта;
- `(connect_timeout, read_timeout)` и различие стадий сбоя;
- `RetryPolicy(max_attempts, retryable_statuses, allowed_methods, budget_seconds, backoff_cap, jitter)`; `max_attempts` включает первую попытку;
- GET/HEAD идемпотентны по контракту; POST по умолчанию не повторяется. ClickHouse SELECT через POST получит отдельный opt-in в 2.11;
- `408`, `429`, часть `5xx`, сетевые исключения по стадии; `Retry-After`; экспоненциальная пауза с jitter;
- внедряемые clock/sleeper/RNG для проверок без реального sleep; исключение `HttpError` без секретов и полного payload.
**Материалы:** Requests, [Timeouts](https://requests.readthedocs.io/en/latest/user/quickstart/#timeouts), [Session Objects](https://requests.readthedocs.io/en/latest/user/advanced/#session-objects); urllib3, [`Retry`](https://urllib3.readthedocs.io/en/stable/reference/urllib3.util.html#urllib3.util.Retry) — allowed methods, counters, backoff, jitter и `Retry-After`; RFC 9110, [Idempotent Methods](https://www.rfc-editor.org/rfc/rfc9110.html#name-idempotent-methods).
**Ход сессии:**
1. Преподаватель объясняет connect/read и retry budget на временной шкале. Ученик предсказывает верхнюю оценку пауз и отдельно называет, почему она не равна жёсткой wall-clock гарантии.
2. Ученик пишет `transport.request(...)` и `RetryPolicy`; JSON-разбор остаётся в `codecs.py`.

## Урок 2.11. Readonly-клиент ClickHouse: transport и NDJSON

**Цель:** ученик пишет клиент чтения ClickHouse с потоковым HTTP-ответом, жёстким клиентским лимитом байтов до накопления тела, разделёнными transport/NDJSON codec, readonly-контрактом и серверными лимитами; production smoke выполняет только заранее одобренные SELECT.
**До урока:** 2.10: `Transport` и retry policy; доступны подтверждённые readonly metadata и профиль лимитов. Если их нет, весь урок проходит на fake/local изолированной среде.
**Объём:** до трёх сессий. Никаких production INSERT/DDL, даже «для проверки запрета».
**Вводная:** `FORMAT JSONEachRow` возвращает NDJSON: отдельный JSON-объект в каждой строке. Это не один JSON-документ. HTTP 200 также не гарантирует, что поток завершился без поздней ошибки. Если сначала обратиться к `response.content`, тело уже окажется в памяти и последующая проверка размера запоздает. Поэтому клиент запрашивает потоковый ответ, считает каждый полученный chunk до добавления в буфер и закрывает response на любом пути. `LIMIT` ограничивает число строк результата, но не стоимость чтения, JOIN, GROUP BY или ORDER BY. Защита складывается из readonly-роли, серверного профиля ресурсов, restricted client contract и bounded результата.
**Темы:**
- SQL SELECT отправляется POST как bytes/text; ответ JSONEachRow разбирает отдельный NDJSON codec;
- минимальная модель Requests streaming: `stream=True` откладывает загрузку тела; `response.iter_content(chunk_size=...)` выдаёт порции bytes, а `with response:` гарантирует `close()` при нормальном завершении и исключении. Здесь достаточно знакомого цикла `for` и уже введённого `with`; собственный генератор писать не требуется;
- `ClickHouseClient.query` владеет открытым response от получения до закрытия. До расширения внутреннего буфера он проверяет `bytes_seen + len(chunk) <= max_result_bytes`; превышающий лимит chunk не материализуется в составе полного тела, частичный результат не возвращается;
- allowlist одного statement: только `SELECT`/`WITH ... SELECT` из доверенного template API; произвольный SQL не «чинится» поиском подстроки `LIMIT`;
- параметры ClickHouse передаются параметризованно; template ID/hash отделён от значений;
- сервер: readonly grant/profile, `max_execution_time`, rows/bytes to read, result rows/bytes, memory и overflow mode; клиент эти настройки не заменяет;
- `query_id`, `wait_end_of_query=1` для малого bounded-ответа; построчный bounded decode проверяет UTF-8, полную строку и остаток на EOF, а также late plain-text/error tail;
- SELECT-over-POST повторяется только с явным idempotent opt-in и policy 2.10;
- privacy logging: query ID, template/hash, duration, status, read/result rows/bytes; никаких raw SQL literals, credentials и PII.
**Материалы:** ClickHouse, [HTTP Interface](https://clickhouse.com/docs/interfaces/http), [JSONEachRow](https://clickhouse.com/docs/interfaces/formats/JSONEachRow), [Restrictions on query complexity](https://clickhouse.com/docs/operations/settings/query-complexity), [Query parameters](https://clickhouse.com/docs/interfaces/http#cli-queries-with-parameters).
**Ход сессии:**
1. Преподаватель показывает байтовое тело из двух NDJSON-строк, разбитое на chunks в неудобных местах, и late-error tail. До практики он объясняет `stream=True`, `iter_content` и владение response через `with` без требования писать собственный генератор.

## Урок 2.19. Модель данных: имена, ссылки, изменяемость

**Цель:** ученик понимает, что имя связывается с объектом, предсказывает мутацию общего объекта и локальное повторное связывание и осознанно выбирает псевдоним, копию или глубокую копию.
**До урока:** урок 2.18; артефакты `campaign-report` и `crm-tools` работают, тесты зелёные.
**Темы:**
- имя связывается с объектом; присваивание не копирует; при вызове локальное имя параметра связывается с переданным объектом (call by sharing): мутация общего mutable object видна вызывающему, локальное повторное связывание — нет
- `==` против `is`: равенство значений против идентичности объекта; почему `None` проверяют через `is`
- изменяемость всерьёз: «функция испортила мой список», срез как поверхностная копия; ловушка изменяемого значения по умолчанию из 2.2 — теперь через механизм «объект по умолчанию создаётся один раз при определении функции»
- `copy` против `deepcopy`: где поверхностной копии хватает и где вложенные структуры требуют глубокой
- хешируемость: что делает `hash()`, почему ключ словаря и элемент set должны быть хешируемыми; неизменяемость сама по себе недостаточна — кортеж со списком не хешируем. Для собственных классов важны согласованность `__eq__` и `__hash__` и стабильность хеша; общий запрет изменяемых объектов был бы неточным

## Урок 2.19a. Сложность, ограниченная память и контейнеры

**Цель:** ученик оценивает рост времени и памяти по входу, выбирает bounded top-N и видит, что генератор источника не ограничивает память потребителя.
**До урока:** 2.19: имена, объекты, копии и контейнеры; 2.4: сортировка и генераторные выражения.
**Объём:** две сессии с воспроизводимыми синтетическими нагрузками.
**Вводная:** два решения могут давать одинаковый ответ на десяти строках и расходиться на миллионе. Оцениваем, сколько элементов хранится и сколько сравнений требуется. Замер подтверждает модель, но не заменяет её.
**Темы:**
- качественная Big O для линейного прохода, lookup dict/set, сортировки и копирования; средний и худший случай без доказательств алгоритмов;

- shallow/deep copy как стоимость по числу объектов;

**Материалы:** Python 3.14, [TimeComplexity](https://wiki.python.org/moin/TimeComplexity) как справочная таблица CPython-контейнеров; `heapq`, [Theoretical Notes](https://docs.python.org/3.14/library/heapq.html#theory); `tracemalloc`, [Examples](https://docs.python.org/3.14/library/tracemalloc.html#examples).
**Ход сессии:**

4. Ученик проектирует агрегатор отчёта: сумма/счётчики однопроходно, top-N ограниченным heap, группировка всех строк помечается как небезразмерная операция.

- Отчёт после рефакторинга «вроде такой же» → сверка на глаз вместо эталона → напомнить приём из 2.7: зафиксировать вывод «до» в файл и сравнить `diff`.
- Тесты ходят в прод или падают без интернета → в тесте не подменён HTTP-слой → спросить: «Какие компоненты здесь настоящие? Какие подменены? Где monkeypatch?»
- Секрет попал в код или в git → привычка «быстро захардкожу, потом уберу» → остановить сессию, показать поиск по истории git; если утёк реальный ключ — сменить ключ; одного удаления коммита недостаточно.
- Красная сборка CI при зелёных локальных тестах → в CI нет секретов/сети либо не тот шаг установки зависимостей → навести на чтение журнала сборки: найти упавший шаг, воспроизвести локально той же командой.
- Урок буксует на упражнениях exercism (перфекционизм) → попытка отполировать решение до идеала задерживает переход к разбору и следующей теме → напомнить: упражнения — разминка, артефакт урока важнее.
- «Функция испортила мой список/словарь» → передан псевдоним; копия не создавалась; мутация видна у вызывающего → навести на `id()` до и после вызова; обсудить выбор: копировать или честно мутировать и назвать это в имени функции.
- Генератор «пустой» при повторном использовании → итератор одноразовый, первый проход его исчерпал → спросить: «Сколько раз ты по нему проходишь? Что возвращает `next()` сейчас?»
- После декоратора у функции чужое имя и пропал docstring → обёртка без `functools.wraps` → показать `f.__name__` до и после, добавить wraps.
- `groupby` даёт несколько групп одного ключа → API группирует только соседние элементы. Если контракт требует глобальную группу, сортировать тем же key; если нужны последовательные runs/sessionization, сортировка запрещена.
- Даты сравниваются как строки и дают неверный порядок → выполняется сравнение `str`; нужны объекты `date`; формат «дд.мм.гггг» лексикографически не сортируется → навести на `strptime` в момент загрузки, сравнение уже объектов `date`.
- `python3 -m venv .venv` падает с «ensurepip is not available» → Ubuntu выносит части стандартной библиотеки в отдельные apt-пакеты (`python3.X-venv`; pip системного python — тоже отдельный пакет) → поставить пакет из подсказки через sudo (законный случай: apt пишет в системные папки root) и проверить, не осталась ли частичная `.venv` от упавшего запуска.
- Опечатка в строке .gitignore (например, `promt-logs/`) → защита молча не работает: папку с правильным именем git закоммитит → приём: сверять записи посимвольно с эталоном; после `git add` контролировать `git status` — не заехало ли лишнее.
- VS Code всплывашка «Ошибка при обновлении пакетов» (Python Environments), в логе `No module named pip` у `/usr/bin/python3` → расширение опрашивает выбранный интерпретатор, а выбран системный python без pip → безвредно; уходит после создания `.venv` в проекте и выбора его интерпретатором.
