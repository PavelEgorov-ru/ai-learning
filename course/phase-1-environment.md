Цель фазы: проверить и освоить уже установленную рабочую среду — WSL/Ubuntu, терминал, VS Code через Remote-WSL и git; удалённый GitHub-контур подключать только по отдельному явному разрешению.

## Урок 1.1. WSL/Ubuntu и файловая система

**Цель:** проверить существующую установку WSL с Ubuntu и уверенно ориентироваться в файловой системе Linux из терминала.
**До урока:** ничего — первый урок курса; WSL с Ubuntu уже установлен. Урок не переустанавливает WSL, не удаляет дистрибутив и не сбрасывает домашний каталог.
**Темы:**
- что такое WSL (подсистема Windows для Linux) и почему код живёт в файловой системе Linux (`~/...`), а не в `/mnt/c` — скорость, права, совместимость инструментов;
- проверка существующего WSL 2, Ubuntu, текущего пользователя и домашнего каталога без переустановки и удаления;
- устройство файловой системы: корень `/`, домашняя папка `~`, абсолютные и относительные пути;
- навигация и операции с файлами: pwd, ls, cd, mkdir, cp, mv, rm, cat, less;
- мост между мирами: `\\wsl$\...` из проводника Windows и `/mnt/c` из Ubuntu; правило «код храним в `~`».

**Материалы:** объяснение репетитора.

5. Обсуждение: `\\wsl$` против `/mnt/c`, почему проект не кладём на диск C.

**Задание:** создать структуру `~/study` (`notes/`, `data/`), завести файл `notes/terminal-cheatsheet.md` и записать туда все команды урока с примером использования каждой; открыть шпаргалку из проводника Windows через `\\wsl$` и убедиться, что это тот же файл.

## Урок 1.5. git и GitHub

**Цель:** освоить локальный цикл git и понимать подключение GitHub; локальные записи истории и любые удалённые действия выполнять только после явного разрешения ученика.
**До урока:** уроки 1.1–1.4 пройдены. Аккаунт GitHub нужен только для отдельно разрешённой удалённой части; без него урок полностью проходит локально.
**Темы:**
- зачем история: снимки состояния проекта, откат, история как дневник курса;
- git init, status, add, commit; что такое область подготовки (staging);
- .gitignore: `__pycache__/`, `.env`, папка выгрузок с персональными данными — не коммитим никогда;
- GitHub: ключ SSH, пустой репозиторий, remote, push и pull;
- осмысленные сообщения коммитов; различие между учебным описанием команды и разрешением выполнить commit или push.

**Материалы:** объяснение репетитора.
**Ход сессии:**
1. Разбор: схема «рабочая папка → staging → коммит», зачем .gitignore.
2. После явного разрешения на локальные Git-действия ученик делает `git init` в `~/study`, пишет `.gitignore`, переносит учебный CSV из `data/` в `data-mock/`, оставляет `data/` для локальных выгрузок и исключает её из Git. Затем выполняет `git status`, `git diff`, `git add` и учебные `git commit` с осмысленными сообщениями.
3. Репетитор объясняет SSH-ключ, пустой GitHub-репозиторий, `remote`, `push` и `pull`. Создание ключа, удалённого репозитория, привязка remote и push выполняются только после отдельного явного разрешения на удалённые действия.
4. Проверка локального пути: изменить шпаргалку → `git status` и `git diff` → после разрешения подготовить и записать второй локальный commit → увидеть изменение в `git log`. Если удалённая часть разрешена, отдельно выполнить push и сверить GitHub; если нет — зафиксировать, что remote не создан и push не выполнялся.
5. Обсуждение: что никогда не попадает в репозиторий (.env, выгрузки с почтами/телефонами) и почему.

**Задание:** подготовить локальный репозиторий `study`: `.gitignore` минимум с `__pycache__/`, `.env` и `data/`; учебный CSV перемещён в `data-mock/`. После явного разрешения на локальные commits создать минимум два осмысленных снимка. GitHub-репозиторий, remote и push — отдельная необязательная часть только по явному запросу; без разрешения ученик словами разбирает точную последовательность команд и остаётся на локальном результате.
**Артефакт:** локальный git-репозиторий `study` — дом артефактов фазы. При отдельном разрешении у него появляется GitHub-remote. В 2.1 отдельный репозиторий `py-template` получает шаблон проекта, а удалённый CI в 2.17 имеет локальную альтернативу.
**Критерий готовности:** ученик объясняет и показывает цикл `status → diff → add → commit` на разрешённой локальной практике, читает `git log --oneline` и объясняет, почему `.env` и `data/` исключены. Если commits не разрешены, критерий проверяется в одноразовой локальной песочнице только после отдельного согласия либо разбором подготовленного репетитором репозитория; GitHub и push не обязательны. Удалённая часть засчитывается только по фактическому разрешённому прогону.

## Банк опорных вопросов и типовых ошибок (для репетитора)

Материал для разбора ошибок и практического повторения по всей фазе; правила использования — в 00-overview.md.

Опорные вопросы для разбора и повторения:
1. Почему код курса живёт в `~`, а не в `/mnt/c`? Что теряется при работе с диска C?
2. Чем абсолютный путь отличается от относительного? Куда ведут `~`, `.` и `..`?
3. Что делает конвейер `cut -d',' -f3 file.csv | sort | uniq -c` по шагам?
4. Чем `>` отличается от `>>` и куда уходит `2>`?
5. Как убить зависший процесс: какие шаги от «висит» до «убит по PID»?
6. Что даёт `chmod +x` и почему без него `./hello.sh` не запускается?
7. В чём разница между `export VAR=...` в текущей сессии и строкой в `.bashrc`? Когда `.bashrc` перечитывается?
8. Почему расширения VS Code ставятся «в WSL: Ubuntu», а не просто в Windows?
9. Что такое staging (область подготовки) в git и зачем нужен отдельный шаг `add` перед `commit`?
10. Что обязано лежать в `.gitignore` с первого дня и почему «удалить секрет коммитом позже» не работает?

Типовые ошибки и затыки:
- Файлы «пропали» или проект тормозит → работа идёт в `/mnt/c` вместо `~`, либо ученик потерялся в дереве каталогов → спросить: «Что показывает `pwd`? Где по правилу курса живёт код?»
- `rm` удалил не то → относительный путь из неожиданной текущей папки → приучить: перед опасной командой `pwd` и `ls`, а для тренировок — отдельная папка-песочница.
- Конвейер выдаёт пустоту или мусор → звенья проверялись только целиком → навести на приём «собирай слева направо, смотри вывод после каждого `|`».
- Алиасы и `$STUDY_HOME` «не работают» → `.bashrc` изменён, но не перечитан (нет `source` и нового терминала), либо опечатка без пробелов вокруг `=` → спросить: «Когда оболочка читает .bashrc? Что изменилось после открытия нового окна?»
- `./hello.sh: Permission denied` → нет бита исполнения → навести на `ls -l` и чтение прав rwx.
- VS Code открыл папку, но Python «не видит» пакетов и терминал — Windows → окно без пометки «WSL: Ubuntu» (открыто не через `code .` из WSL) → проверить надпись в левом нижнем углу.
- `git push` отклонён (Permission denied / repository not found) → ключ SSH не добавлен в GitHub или remote указывает не туда → навести на `ssh -T git@github.com` и `git remote -v`.
- Закоммичен лишний файл (кэш, черновик, потенциально секрет) → коммит «всего подряд» через `git add .` без `git status` → приучить смотреть `git status` и `git diff` перед каждым коммитом; если попал секрет — правило из 2.16: менять секрет, а не историю.
- Ключ «точно правильный», но команда отвечает `unexpected argument` → кириллическая буква вместо латинской (`-с` из русской раскладки) → перенабрать ключ латиницей; та же ловушка живёт в шпаргалках — проверять поиском по кириллическому ключу (реальный случай урока 1.2).
- Конвейер собран, но ответ странный или цепочка «не влияет» → последнему звену передано имя файла, а команда с файлом-аргументом игнорирует stdin → напомнить правило «имя файла — первому звену, дальше только труба» (реальный случай урока 1.2).
- Концовка конвейера отвечает не на заданный вопрос → путает «сколько в каждой группе» (`sort | uniq -c`) и «сколько всего разных» (`sort | uniq | wc -l`) → спросить: «что должно быть на выходе — одно число или таблица?» (реальный случай урока 1.2).
- Алиас назван именем существующей команды (например, `alias rmdir="rm -rf"`) → имя не проверено перед выбором, плюс привычка к `-f` по умолчанию → навести на `type имя` перед созданием алиаса; правило: перекрывать своим алиасом можно алиас, но не команду; `-f` — только когда подавление проверок является целью (реальный случай урока 1.3).
- В `.bashrc` переопределена системная переменная (`HOME=...`) → ученик решил, что `$HOME` надо определить перед использованием → объяснить: HOME/USER/PATH устанавливает система при входе, они гарантированно есть; правило «системные переменные используют, не переопределяют» (реальный случай урока 1.3).
- Переменная окружения «не работает», но ошибок нет → терминал открыт до правки `.bashrc`, несуществующая переменная молча подставляется пустой строкой → спросить: «когда этот терминал прочитал .bashrc? что подставит bash вместо неопределённой переменной?» — связать с будущими секретами: пустой ключ, а не ошибка (реальный случай урока 1.3).
