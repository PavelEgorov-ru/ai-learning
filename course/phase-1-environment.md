# Фаза 1. Среда (5 уроков)

Цель фазы: собрать рабочую инженерную среду — WSL/Ubuntu, терминал, VS Code через Remote-WSL, git и GitHub — и научиться в ней жить.
На выходе ученик: уверенно ориентируется в файловой системе Linux, собирает конвейеры команд, управляет процессами и переменными окружения, работает в настроенном редакторе и ведёт историю кода в git.
Главный артефакт фазы: папка `~/study` — git-репозиторий на GitHub с шпаргалкой терминала, учебным CSV и настройками редактора. Это дом всех артефактов курса: в фазе 2 сюда ложится шаблон проекта и весь код, с урока 1.5 действует правило «коммит в конце каждой сессии».

## Урок 1.1. WSL/Ubuntu и файловая система

**Цель:** установить WSL с Ubuntu и уверенно ориентироваться в файловой системе Linux из терминала.
**До урока:** ничего — первый урок курса; нужен Windows с правами администратора.
**Темы:**
- что такое WSL (подсистема Windows для Linux) и почему код живёт в файловой системе Linux (`~/...`), а не в `/mnt/c` — скорость, права, совместимость инструментов;
- установка WSL 2 с Ubuntu, создание пользователя, первый запуск терминала;
- устройство файловой системы: корень `/`, домашняя папка `~`, абсолютные и относительные пути;
- навигация и операции с файлами: pwd, ls, cd, mkdir, cp, mv, rm, cat, less;
- мост между мирами: `\\wsl$\...` из проводника Windows и `/mnt/c` из Ubuntu; правило «код храним в `~`».

**Материалы:** объяснение репетитора.
**Ход сессии:**
1. Разбор: зачем WSL, карта файловой системы, где будет жить проект.
2. Ученик ставит WSL 2 и Ubuntu, создаёт пользователя, открывает терминал.
3. Руками: создать `~/study` с подпапками `notes/` и `data/`, потренировать навигацию и операции с файлами.
4. Проверка запуском: репетитор диктует 5 задач на навигацию и операции — ученик выполняет в терминале без подсказок.
5. Обсуждение: `\\wsl$` против `/mnt/c`, почему проект не кладём на диск C.

**Задание:** создать структуру `~/study` (`notes/`, `data/`), завести файл `notes/terminal-cheatsheet.md` и записать туда все команды урока с примером использования каждой; открыть шпаргалку из проводника Windows через `\\wsl$` и убедиться, что это тот же файл.
**Артефакт:** папка `~/study` и шпаргалка терминала. Папка — рабочее место всего курса; шпаргалка дополняется в уроках 1.2–1.3 и уходит в git в уроке 1.5.
**Критерий готовности:** ученик выполняет подряд 5 устных задач репетитора («перейди в…, создай…, переименуй…, покажи содержимое…») без подсказок; проверка: `ls -R ~/study` показывает структуру, шпаргалка открывается из Windows.

## Урок 1.3. Процессы, права, переменные окружения, .bashrc

**Цель:** управлять процессами, понимать права на файлы и настроить свою оболочку через переменные окружения и .bashrc.
**До урока:** ничего, кроме предыдущего урока (уроки 1.1–1.2 пройдены).
**Темы:**
- процессы: ps, htop, запуск в фоне `&`, Ctrl+C и Ctrl+Z, jobs/fg/bg, kill по PID;
- права rwx на файлы, chmod, `chmod +x` для скриптов; sudo — когда нужен, а когда вреден;
- переменные окружения: export, PATH, env, `echo $VAR`; зачем это секретам (задел на .env в уроке 2.16);
- .bashrc: алиасы (короткие имена команд), когда файл читается, перезагрузка через source;
- установка пакетов: apt update / apt install (поставить ripgrep и htop).

**Материалы:** объяснение репетитора.
**Ход сессии:**
1. Разбор: жизнь процесса, схема прав rwx, откуда берутся переменные окружения.

4. Проверка запуском: новый терминал подхватывает алиасы и переменную; `./hello.sh` запускается только после `chmod +x`.
5. Обсуждение: переменные окружения как будущее место секретов; разница «export в сессии» и «строка в .bashrc».

**Задание:** настроить `~/.bashrc`: 3–5 полезных алиасов (например, ll и быстрый переход в `~/study`) и переменная STUDY_HOME; написать и сделать исполняемым `hello.sh` (выводит имя пользователя и значение STUDY_HOME); дописать в шпаргалку раздел «процессы, права, окружение».

## Банк опорных вопросов и типовых ошибок (для репетитора)

Материал для квизов и повторения по всей фазе; правила использования — в 00-overview.md.

Опорные вопросы (для квизов и повторения):
1. Почему код курса живёт в `~`, а не в `/mnt/c`? Что теряется при работе с диска C?
2. Чем абсолютный путь отличается от относительного? Куда ведут `~`, `.` и `..`?
3. Что делает конвейер `cut -d',' -f3 file.csv | sort | uniq -c` по шагам?
4. Чем `>` отличается от `>>` и куда уходит `2>`?
5. Как убить зависший процесс: какие шаги от «висит» до «убит по PID»?
6. Что даёт `chmod +x` и почему без него `./hello.sh` не запускается?
7. В чём разница между `export VAR=...` в текущей сессии и строкой в `.bashrc`? Когда `.bashrc` перечитывается?
8. Почему расширения VS Code ставятся «в WSL: Ubuntu», а не просто в Windows?
9. Что такое staging (область подготовки) в git и зачем нужен отдельный шаг `add` перед `commit`?
10. Что обязано лежать в `.gitignore` с первого дня и почему «удалить секрет коммитом позже» не работает?

Типовые ошибки и затыки:
- Файлы «пропали» или проект тормозит → работа идёт в `/mnt/c` вместо `~`, либо ученик потерялся в дереве каталогов → спросить: «Что показывает `pwd`? Где по правилу курса живёт код?»
- `rm` удалил не то → относительный путь из неожиданной текущей папки → приучить: перед опасной командой `pwd` и `ls`, а для тренировок — отдельная папка-песочница.
- Конвейер выдаёт пустоту или мусор → звенья проверялись только целиком → навести на приём «собирай слева направо, смотри вывод после каждого `|`».

- `./hello.sh: Permission denied` → нет бита исполнения → навести на `ls -l` и чтение прав rwx.

- Конвейер собран, но ответ странный или цепочка «не влияет» → последнему звену передано имя файла, а команда с файлом-аргументом игнорирует stdin → напомнить правило «имя файла — первому звену, дальше только труба» (реальный случай урока 1.2).
